# Assets

Binary artifacts that documentation and issues embed — screenshots, diagrams
exported as images. Nothing here is prose: every file exists because some
Markdown, or some GitHub issue, points at it. The directory starts empty.

## Conventions

- **Commit a binary only when a tracked document or issue references it**, and
  say where it came from — generated by which script, or captured from which
  screen. An asset nothing points at is weight every clone pays for.
- **Name it after what it documents.** `issue-<NN>-<slug>.png` for a frame tied
  to one issue; `YYYY-MM-DD-<slug>.png` for one captured before it has a ticket.
  Group by purpose in subdirectories (`qa/` for defect evidence, `ui/` for
  component screenshots).
- **A screenshot that reports a visual defect is the defect report.** An issue
  that describes the defect only in prose has lost its evidence. When the
  repository is private, GitHub issue attachments are not reliably linkable, so
  commit the frame here on a branch and link it from the issue.
- **Link by commit SHA, not by branch:**
  `https://github.com/<owner>/<repo>/blob/<sha>/docs/assets/<file>.png?raw=true`.
  The link works as soon as the branch is pushed and survives the branch being
  deleted after merge.
- **Generated images are regenerated, never hand-edited.** If a script produces
  them, name the script in the document that embeds them.
- Prefer Mermaid in Markdown over an image for any diagram that can be text;
  it diffs and reviews like code.
