# Portal — web

React + TypeScript SPA, served same-origin behind the Spring BFF in
[`../bff`](../bff) under `/app/`. See [`../README.md`](../README.md) for how the
two halves fit together and [`../CLAUDE.md`](../CLAUDE.md) for the rules that
govern changes here. The source is organized by **Feature-Sliced Design**;
[ADR-027](../../docs/adr/ADR-027-feature-sliced-design-for-the-spa.md) records
why, and this file is how to work in it.

Stack: React 18, MUI 5, React Query 5, react-router 6 (data router), i18next,
`openapi-fetch` with types generated by `openapi-typescript`, Vite 5, Vitest +
Testing Library, Playwright + axe, ESLint (with `eslint-plugin-boundaries`) and
Prettier.

## Commands

Run from `portal/web/` (Node 20):

| Command | What it does |
| --- | --- |
| `npm run dev` | Vite dev server; proxies `/app/bff`, `/app/health`, `/app/about` to the BFF on `localhost:8081`. |
| `npm run generate:api` | Regenerates `src/shared/api/generated/portal-api.d.ts` from `../../docs/arch/api-layer/portal-api-v1.yaml`. Runs before `build`, `test`, `test:coverage`, `typecheck` and `lint`. |
| `npm run typecheck` | `tsc --noEmit` (strict) over both projects: `tsconfig.json` (the browser code) and `tsconfig.node.json` (the Playwright suites, their config and the Vite config). |
| `npm run lint` | ESLint, type-aware — typescript-eslint, react-hooks, react-refresh, jsx-a11y, and the layering rules below — with `--max-warnings 0`. |
| `npm run format` / `npm run format:check` | Prettier: write the formatting / fail on a file that differs. |
| `npm test` | Vitest, once. The fast inner loop — holds no coverage floor. |
| `npm run test:coverage` | Typecheck, then Vitest with the coverage ratchet. **This is the gate CI runs**, with `lint` and `format:check`. |
| `npm run build` | Typecheck + production build into `dist/`. |
| `npm run test:a11y` | Playwright + axe against `vite preview` of the production build (run `npm run build` first). |
| `npm run test:journey` | Playwright against a running stack at `E2E_BASE_URL`; fails when it is unset. |

## The folder structure

Six **layers**, top to bottom. A layer imports only the layers below it.
`pages`, `widgets`, `features` and `entities` are cut into **slices** (by
business meaning); a slice is cut into **segments** (by technical purpose:
`ui`, `model`, `api`, `lib`, `config`). `app` and `shared` have segments only.
Every slice and every `shared` segment exposes a **public API**, its `index.ts`.

```
src/
  main.tsx                  the Vite entry: mounts `@/app` and nothing else
  app/                      the composition root — may import every layer
    App.tsx                 providers + RouterProvider + the global error snackbar
    index.ts                public API: registers the fonts, exports App
    providers/              ColorModeProvider (the mode's state), queryClient (the error net's wiring)
    router/                 router.tsx (the route tree: lazy pages, errorElement, titleKey), RouteError
    styles/                 fonts.ts (the self-hosted font faces)
    __tests__/              suites of the app modules; guards/ — the whole-tree guards
  pages/                    one slice per route
    home/                   /           the landing page
    items/                  /items      the example aggregate's list, composing edit-item and delete-item
    build/                  /build      which build of the portal and the API runs (its queries live here)
    not-found/              *           the catch-all
  widgets/
    shell/                  the frame every page renders in: Shell, Nav, TopBar, IdentityCard,
                            ShellLayout (the root route's element), ContentFallback,
                            navItems (the rail's destinations), useNavCollapsed, geometry
  features/                 what a user does
    edit-item/              ItemDialog — create or edit an item, save, invalidate
    delete-item/            DeleteItemDialog — confirm, delete, invalidate
    change-language/        LanguageSelector
    toggle-color-mode/      ToggleColorModeButton
    logout/                 LogoutButton
  entities/                 what the product is about
    item/                   the example aggregate: its types, itemKeys/itemQueries, the form model (itemForm)
    user/                   the signed-in caller: userQueries, initialsOf
  shared/                   knows nothing of the product
    api/                    client.ts (every call to the BFF), auth.ts (CSRF + login redirect),
                            apiError.ts, errorReporting.ts (the global net), generated/ (contract types)
    ui/                     the primitives: PageHeader, DataTable + useClientSort, Banner, ApiErrorBanner,
                            ConfirmDialog, SectionCard, KeyValueList, FooterNote, GlobalErrorSnackbar
    lib/                    pageState, useDocumentTitle / useRouteTitle, visuallyHidden
    theme/                  tokens, buildTheme, contrast helpers, the color-mode context
    i18n/                   the i18next instance (initialized on import), locales/<tag>.json
    testing/                the suites' harness — render helpers, t(), the console guard (setup.ts)
e2e/                        Playwright: *.a11y.spec.ts, *.journey.spec.ts, i18n.ts (key resolver)
```

### Import rules

| From | May import |
| --- | --- |
| `app` | `pages`, `widgets`, `features`, `entities`, `shared` |
| `pages` | `widgets`, `features`, `entities`, `shared` |
| `widgets` | `features`, `entities`, `shared` |
| `features` | `entities`, `shared` |
| `entities` | `shared` |
| `shared` | other `shared` segments |

Always through the target's public API, and always with the `@/` alias when the
import crosses a slice or a layer. Inside a slice, import relatively.

```ts
// in pages/items/ui/ItemsPage.tsx
import { itemQueries, type Item } from "@/entities/item";     // yes — downward, public API
import { DeleteItemDialog } from "@/features/delete-item";    // yes
import { PageHeader, DataTable } from "@/shared/ui";           // yes

// in features/delete-item/ui/DeleteItemDialog.tsx
import { ItemDialog } from "@/features/edit-item";             // no — sideways: two slices of one layer
// in entities/item/api/itemQueries.ts
import { ItemsPage } from "@/pages/items";                     // no — upward
// anywhere outside entities/item
import { validateItem } from "@/entities/item/model/itemForm"; // no — past the public API
import { validateItem } from "../../../entities/item";         // no — use the alias
```

`npm run lint` enforces all of it (`eslint-plugin-boundaries`, see
`eslint.config.js`), and `src/app/__tests__/guards/boundaries.test.ts` proves
the rules still fire against planted violations.

### Where a new piece of code goes

Ask, in this order:

1. **Does it know nothing about the product** — a primitive, a helper, the
   theme, the API client? → `shared`, in the segment of its purpose.
2. **Is it a business object** the product is about — its types, its queries,
   its form model? → `entities/<name>`.
3. **Is it something a user does** — an action with a control and usually a
   mutation? → `features/<verb-noun>`.
4. **Is it a large block several pages show** — composed of features and
   entities? → `widgets/<name>`.
5. **Is it a screen**, or code only one screen needs? → `pages/<route>`.
6. **Is it wiring** — a provider, the route tree, global styles? → `app`.

**Pages first.** When unsure, keep code in the page that needs it (the build
page's queries are `pages/build/api/`), and move it down a layer when a second
consumer appears. A slice may not import another slice of its own layer, so
code two slices share moves *down*, never sideways.

### Naming

- Folders — layers, slices, segments — are **kebab-case** (`delete-item`), or
  `__tests__`.
- A component is **`PascalCase.tsx`**, named after the component it exports.
- A hook is **`useX.ts`** and exports `useX`.
- Any other module is **`camelCase.ts`**, named after its principal export
  (`apiError.ts` → `ApiError`, `itemQueries.ts` → `itemQueries`) or, failing
  one, the singular noun of its responsibility (`geometry.ts`).
- A slice's or segment's public API is **`index.ts`**.
- Generated code lives only in `generated/`; locale bundles are named by tag.

`src/app/__tests__/guards/structure.test.ts` checks every one of these.

### Tests

- A suite is **`<module>.test.ts(x)`**, named after the module it tests, in the
  **`__tests__/`** folder of the slice or segment that holds the module
  (`pages/items/__tests__/ItemsPage.test.tsx`). It imports its own slice
  relatively and everything else through the alias.
- The **guards** — contract, bundles, key rule, error inventory, typecheck
  wiring, layout, and the layering self-test — hold invariants of the whole
  tree, so they live together in `src/app/__tests__/guards/`, named after what
  they guard. `app` is the one layer allowed to see every other.
- The harness is **`@/shared/testing`**: `renderWithProviders`, `renderRoutes`
  (the data router), `t` / `tRe` (assert keys, never copy), `expectConsole`
  (declare expected console output; anything else fails the test). Production
  code may not import it.
- Mock the API at its module: `vi.mock("@/shared/api/client", …)`, then set
  each function's answer in the `beforeEach` or the test that relies on it.

## Adding a feature

For a new resource `<name>` (plural, English), in this order:

1. **Contract.** Add the operations to `docs/arch/api-layer/openapi-v1.yaml` and
   their proxied twins, with `x-proxies-to`, to `portal-api-v1.yaml`.
2. **Generate.** `npm run generate:api`, then `npm run typecheck`.
3. **Calls.** Add the typed functions to `src/shared/api/client.ts` and export
   them, with the schema types, from `src/shared/api/index.ts`.
4. **Entity.** `src/entities/<name>/`: `api/<name>Queries.ts` (a key factory
   and `queryOptions`), `model/<name>Form.ts` if there is a form (limits
   mirrored from the contract), and `index.ts` exporting them.
5. **Features.** One slice per user action, e.g. `src/features/edit-<name>/`
   and `src/features/delete-<name>/`: the dialog in `ui/`, its `useMutation`
   inline with `meta: REPORTED_INLINE` when it renders its own failure, and an
   invalidation of the entity's root key on success.
6. **Page.** `src/pages/<name>/ui/<Name>Page.tsx` composes the entity's query
   and the features, with `PageHeader`, `pageStateOf` and `ApiErrorBanner`;
   `src/pages/<name>/index.ts` exports it.
7. **Route.** In `src/app/router/router.tsx`: an English path segment that is
   not `bff`, `about` or `health`, `lazy` for the page,
   `errorElement: <RouteError />` and `handle: titled("<name>.title")`.
8. **Navigation.** An entry in `src/widgets/shell/model/navItems.ts`.
9. **Copy.** Every new key in **both** `src/shared/i18n/locales/*.json`.
10. **Tests.** Suites in each new slice's `__tests__/`; `client.test.ts` cases
    for the calls; the route in `e2e/portal.a11y.spec.ts`'s `ROUTES`; raise the
    floors of the guards that count modules and suites when they ask to.
11. **Verify.**
    `npm ci && npm run lint && npm run format:check && npm run test:coverage && npm run build`,
    then `npm run test:a11y`.

The step-by-step with the practices behind each step is
[`docs/dev/frontend-standards.md`](../../docs/dev/frontend-standards.md) §14.

## Routes

| Path (under `/app`) | Slice | Screen |
| --- | --- | --- |
| `/` | `pages/home` | A landing page linking to the items. |
| `/items` | `pages/items` | Items — list, create, edit, delete. |
| `/build` | `pages/build` | Build information of the portal and of the API. |
| anything else | `pages/not-found` | Not found, inside the shell. |

`/app/bff/**`, `/app/about` and `/app/health` belong to the BFF, so no client
route may start with `bff`, `about` or `health`; `apiContract.test.ts` walks
the route tree and the navigation and checks them against the contract.

Every route renders inside the shell and declares an `errorElement` (a screen
that throws, or whose chunk fails to load, is replaced by `RouteError` inside
the shell) and a `handle.titleKey` (the document title, `<page> · <app>`).
Screens beyond the landing page are loaded on demand (`lazy`).

## Design system

`src/shared/theme/` holds the design tokens (brand ramp, ink, surfaces,
borders, semantic colors, radii, elevation, font stacks) and maps them onto MUI
in both light and dark modes (`buildTheme`); components read the raw tokens as
`theme.app`. The first render follows `prefers-color-scheme`, and the top bar
toggles it (`features/toggle-color-mode`).

WCAG 2.2 AA is held twice: `src/shared/theme/__tests__/buildTheme.test.ts`
asserts every text/control pair of the palette in both modes, and the `a11y`
Playwright project runs axe over every route in both themes, at 320px, and with
reduced motion. A brand swap is an edit to `tokens.ts` that those two then
accept or refuse.

Three families are self-hosted through `@fontsource` (no external CDN):
Archivo (display, 500–800), IBM Plex Sans (body, 400–600) and IBM Plex Mono
(identifiers, 400–500). Keep the imported weights in `src/app/styles/fonts.ts`
deliberate — each one is shipped.
